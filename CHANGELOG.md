# Changelog

All notable changes to `@absolutejs/git`.

`changelog/`. Edit an entry, not this file — and add new ones under

## 0.26.0 — 2026-11-11

### Added

- **Compare two commits** (`compareGitHubCommits`, `GitHubCommitComparison`)
  compareGitHubCommits says how far apart two commits of a repository are (aheadBy, behindBy and GitHub's status), without listing the commits between them. PAAS uses it to say how far a change has fallen behind the live version.

## 0.25.0 — 2026-11-11

### Added

- **Whether a repository is private** (`GitHubRepositoryMergeSettings`, `getGitHubRepositoryMergeSettings`)
  GitHubRepositoryMergeSettings now carries private: whether only people given access can see the repository, null when GitHub didn't say. A public repository's branch names are public too, so PAAS shows a change's branch name before its first push to one.
- **The merge commit of a merged pull request** (`GitHubPullRequest`, `getGitHubPullRequest`)
  GitHubPullRequest now carries mergeCommitSha: the commit a merge made on the base branch (a squash, a merge commit, or a rebase's last commit), null until the pull request is merged. PAAS uses it to undo a merged change with a revert.

## 0.24.0 — 2026-11-11

### Added

- **Open a pull request as the person** (`createGitHubAppUserClient`)
  createGitHubAppUserClient's createPullRequest opens a pull request with the person's linked GitHub App user credential, so GitHub shows them as its author.

## 0.23.0 — 2026-11-11

### Added

- **Review, comment on, and read the readiness of a pull request** (`commentOnGitHubPullRequest`, `reviewGitHubPullRequest`, `getGitHubPullRequestReadiness`, `GitHubPullRequestReadiness`, `createGitHubAppUserClient`)
  commentOnGitHubPullRequest posts on a pull request's conversation (as the App, with an installation token). reviewGitHubPullRequest submits APPROVE, REQUEST_CHANGES or COMMENT with whatever token it is given, and createGitHubAppUserClient's new reviewPullRequest does it as the person, with their linked credential. getGitHubPullRequestReadiness reads the review decision, merge state and every check on the latest commit, through GraphQL.

## 0.22.1 — 2026-11-10

### Fixed

- **Errors are the same class whichever entry point threw them** (`GitIngestionError`, `GitAuthorizationError`, `GitHubApiError`)
  Each entry point was bundled with its own copy of the package's shared code, so an error thrown by one entry point (GitIngestionError from @absolutejs/git/github-app, say) was never instanceof the class exported by another (@absolutejs/git). Consumers' error handling missed every such error. The build now splits shared code into one chunk.

## 0.22.0 — 2026-11-10

### Added

- **Read what a repository's GitHub settings allow** (`listGitHubBranchRules`, `getGitHubRepositoryMergeSettings`, `GitHubBranchRule`, `GitHubRepositoryMergeSettings`)
  listGitHubBranchRules reads the rules every active ruleset applies to a branch, which need not exist yet, with Metadata read only. getGitHubRepositoryMergeSettings reads which merge methods a repository allows, null where GitHub hides a field.

## 0.21.0 — 2026-11-10

### Added

- **Mark a draft pull request ready for review** (`markGitHubPullRequestReady`, `GitHubPullRequest`)
  markGitHubPullRequestReady marks a draft pull request ready for review through GraphQL's markPullRequestReadyForReview (REST can't change a pull request's draft state), with the pull request's new nodeId; GraphQL errors are thrown with GitHub's message.

## 0.20.0 — 2026-11-09

### Added

- **Send work to GitHub: scoped write tokens and pull requests** (`findGitHubPullRequest`, `getGitHubPullRequest`, `createGitHubPullRequest`, `updateGitHubPullRequest`, `mergeGitHubPullRequest`, `GitHubMergeRefusedError`, `GitHubPullRequest`, `GitHubAppTokenPermissions`)
  createGitHubAppInstallationToken takes permissions, so a write is asked for only by the call that writes; getGitHubAppInstallation and listGitHubAppInstallationsForUser report the permissions an installation has accepted; findGitHubPullRequest, getGitHubPullRequest, createGitHubPullRequest, updateGitHubPullRequest and mergeGitHubPullRequest manage a branch's pull request, and a merge goes through GitHub, so the repository's branch protection and required checks decide (GitHubMergeRefusedError on 405 or 409).

### Changed

- **Installations report their accepted permissions; tokens can be narrowed** (`GitHubAppInstallation`, `createGitHubAppInstallationToken`)
  GitHubAppInstallation gains permissions, what the installation has accepted (an App's new permissions reach an installation only once its owner accepts them). createGitHubAppInstallationToken takes an optional permissions to narrow the token; without it nothing changes.

## 0.19.0 — 2026-10-25

### Added

- **Gate a deploy on a commit's GitHub checks** (`verifyGitHubAppCheckSuiteWebhook`, `listGitHubCommitCheckRuns`, `gitHubChecksVerdict`, `GitHubChecksVerdict`, `GitHubCommitCheckRun`)
  verifyGitHubAppCheckSuiteWebhook reads a signed check_suite completed event; listGitHubCommitCheckRuns lists a commit's latest check runs across every page with the App that owns each; gitHubChecksVerdict says whether they are none, pending, passed or failed, leaving out runs a deployer posts itself.
